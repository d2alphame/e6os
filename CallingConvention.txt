The Calling Convention of e6

This document defines the e6 ABI calling convention used for function calls and return values.
It complements the ABI definition in ABI.txt and should be treated as the normative contract for how parameters and return values are encoded.
It should be noted that all multi-byte values are little endian.

General rules

1. Values are passed according to type category. If more than the designated register slots are needed for a single category, then all values (return values/parameters) are placed into a buffer and the pointer to that buffer is passed in RBX. This applies to both parameters and return values, and the values appear in the same relative order they were supplied or returned.
2. The callee may use the stack for local working space, but must restore RSP before returning.
3. The carry flag is reserved for error signaling.
4. A function may freely overwrite any volatile register, but must preserve all non-volatile registers.

Parameter passing

When making a call:
1. First number goes into RAX.
2. Second number goes into RDX.
3. First string goes into RSI.
4. Second string goes into RDI.
5. First buffer goes into RBX.
6. Second buffer goes into RBP.
7. Count, length, and size values go into RCX.
8. If there are too many parameters of a given type, then all parameters are placed into a memory buffer pointed to by RBX.
9. In that case, the register-passed value(s) are either omitted or replaced by the pointer to that data buffer, depending on the specific API contract.
10. Arrays and structs/records are treated as buffers and are passed in RBX/RBP.
11. The caller is advised to not pass buffers on the stack.

Return values

When returning from a call:
1. Return the first number in RAX.
2. Return the second number in RDX.
3. Use RCX to return count or length values.
4. Return the first string in RSI.
5. Return the second string in RDI.
6. Return the first buffer in RBX.
7. Return the second buffer in RBP.
8. If there are too many return values of a given type, then all values of that type are placed into a memory buffer pointed to by RBX.
9. On success, clear the carry flag.
10. On error, set the carry flag, place the error code in RAX, and place the error string in RSI.
11. The callee must **never** manipulate the caller's stack space unless the caller passed a buffer on the stack.

Other things to note

1. Return buffers are owned by the caller. So when a callee returns a buffer, it is the caller's responsibility to prepare the buffer and also to make the first thing in the buffer its size in bytes.
2. The size of the buffer includes the size field itself.
3. The first item in every buffer is the always the size of the buffer in bytes.
4. The buffer is ideally, but not mandatorily, 8-byte aligned. Programmers should check the API contract for any specific alignment requirements.

Register preservation rules

Registers that are volatile and may be clobbered by the callee:
RAX, RBX, RCX, RDX, RSI, RDI, RBP

Registers that must be preserved across calls:
R8-R15

The callee must also preserve the stack pointer:
RSP must be restored before returning.

The stack is used for nested calls and temporary working space. A callee may push and pop data as needed, but the final RSP value on return must match the caller's expectation.

Data types

1. Strings
Tiny string: a length-prefixed string whose length fits in a single byte, i.e. 0 to 255 bytes
Small string: a length-prefixed string whose length fits in 2 bytes, i.e. 0 to 65535 bytes
Big string: a length-prefixed string whose length fits in 4 bytes, i.e. 0 to 4,294,967,295 bytes
Huge string: a length-prefixed string whose length fits in 8 bytes, i.e. 0 to 18,446,744,073,709,551,615 bytes
RCX string: a string whose length is supplied in RCX
Null-terminated string: terminated by 0
Value-terminated string: terminated by a specific delimiter value

Length-prefix rule:
For tiny, small, big, and huge strings, the string payload is preceded by a length field in the corresponding width (1, 2, 4, or 8 bytes). The full value stored in the register or buffer is therefore the length-prefixed representation, not just the raw bytes.

2. Numbers
Byte: 8-bit unsigned
Signed byte: 8-bit signed
Word: 16-bit unsigned
Signed word: 16-bit signed
Double word: 32-bit unsigned
Signed double word: 32-bit signed
Quad word: 64-bit unsigned
Signed quad word: 64-bit signed

3. Other values
Arrays and buffers are passed as memory regions and are treated like pointer-based values.
Structs and records are treated as buffers and are passed in the same way as arrays.

ABI compatibility notes

1. The ABI is intentionally custom and minimal.
2. All code on the system must agree on the same calling convention.
3. A future ABI change must be versioned and documented in the header and in the calling convention notes.
4. Reserved bits, reserved registers, and reserved stack slots must not be reused silently without a documented ABI revision.
5. The kernel, user programs, and any toolchain or runtime must agree on the same rules for pointer, string, and buffer semantics.
